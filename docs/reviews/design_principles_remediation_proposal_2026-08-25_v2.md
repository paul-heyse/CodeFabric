# Design-principles remediation proposal v2 — unifying the data fabric on DataFusion 55 + Arrow 59

This document supersedes v1 after the plan audit invalidated its
LogicalPlan-only query architecture, universal-IPC boundary, several library
claims, and its treatment of the pass-3 register as current truth. It defines
the target required to achieve full alignment with the 25 data-fabric design
principles. Certification remains conditional on accepted normative-spec
amendments and a detector-backed superseding conformance register; the 124
pass-3 rows are a source worklist, not a current-tree fact table.

**This is a target-design proposal, not an implementation plan.** It names
mechanisms, authorities, contracts, and evidence obligations; it deliberately does
not name modules, files, packet boundaries, or sequencing below the wave level.
The `impl-plan` workflow converts it into dependency-closed packets; `plan-audit`
challenges it before execution.

## 1. Purpose, inputs, and baseline

### 1.1 What changed since the register

The conformance register measured the tree at `d89cc90` under Arrow `=58.4.0` /
DataFusion `=54.1.0` / delta-rs `9f922319`, and recorded the Arrow 59 /
DataFusion 55 references as "research, cited by nothing." That is no longer the
state of the tree. At this proposal's baseline (`f2dfcfe`), the root manifest pins
**Arrow/Parquet `=59.2.0`, DataFusion `=55.0.0`, `object_store` `=0.13.2`, and
delta-rs revision `43a0cf10`** — the exact environment the alignment manual is
written against. The data-fabric upgrade the register treated as future work is
the platform this proposal builds on; every mechanism below is selected for the
pinned 55/59 environment (`ALIGN A.1`, `A.2`, `A.3`; `DFREF §34`, `§40A`).

The register cannot be treated as current without re-execution of every
detector. At least DP-022 was false at its own recorded baseline: production
`update_wave` and `update_wave_item` insert statements already existed in
`src/lifecycle.rs` at `d89cc90` and remain present at this proposal's baseline.
The upgrade and intervening implementation may have closed, changed, or
invalidated other rows. R11 therefore re-derives the register before any
finding-driven implementation begins.

### 1.2 What "full resolution" means here

- Every `CONF` finding DP-001–DP-124 is re-executed and receives a current-tree
  disposition before it can authorize implementation. Section 4 preserves the
  v1 mapping as provenance; the superseding register generated by R11 is the
  implementation authority.
- The four divergence-ledger closures in the register's §6 (tenancy, masking,
  advisory display metadata, user-visible `Expr` transparency) **remain closed**.
  Full alignment does not mean implementing principle clauses the design corpus
  explicitly refuses (§9).
- The five previously unowned principles and DP-051 receive concrete normative
  amendment clauses in §6. Full-alignment certification requires those clauses
  to be accepted into their owning specifications, not merely routed.

### 1.3 Design posture

The alignment manual's constitution governs every move: model the truth once,
compile it through Arrow and DataFusion, keep the optimizer able to see it,
execute through truthful contracts, and preserve identity, state, evidence, and
lineage (`ALIGN` Part VIII). Three postures follow from repository doctrine and
bound what "best-in-class utilization" may mean here:

1. **The extension ladder is honored** (`PRIN P14`, `ALIGN` §2.3). Relational
   work uses built-in `Expr`, `LogicalPlanBuilder`, and `TableProvider`
   capabilities. The semantic-query contract also requires graph traversal,
   path, pattern, and arbitrary DAG semantics that are not assumed to fit
   built-in relational nodes. Those operations use an application-owned typed
   `GraphOperatorPlan` over the existing graph substrate and exchange typed
   Arrow batches with relational subplans. This is not a custom DataFusion
   `ExecutionPlan`, planner hook, UDF, or `LogicalPlan::Extension`; descending
   into those extension levels remains a design-reopening event.
2. **Agents never see SQL or plan syntax** (`SRV §6` inv. 5). DataFusion's
   logical plane becomes the daemon's *internal* compiled representation; the
   semantic-envelope contract (`QRY`) remains the only agent-facing surface.
3. **Python remains presentation only** (`RM §1` inv. 8). Every mechanism that
   computes, validates, or re-derives moves behind the daemon contract.
4. **Protocol follows the boundary** (`PRIN P7`, `P8`, `P22`; `ALIGN INT-01`,
   `INT-08`). In-process Rust providers exchange validated `RecordBatch`
   streams; subprocess providers use validated Arrow IPC and converge on the
   same ingest contract. Serialization is not imposed where no process,
   language, durable, or interoperability boundary exists.

## 2. Resolution thesis — one fabric, one compiler, one authority per concept

The register's three dominant patterns — divided authority (P3), untruthful
capability claims (P20), and proof that names contracts without executing them
(P25) — share one root cause: **the system compiles its contracts into artifacts
but does not execute through them.** Registries are generated and then re-typed
as string literals; schemas are generated and then re-encoded by hand; the query
path bypasses planning with `format!`-built SQL; golden answers are descriptors
rather than outputs. The remediation is therefore not 124 point fixes but a
single architectural commitment, applied through eleven remediation moves:

> **Every semantic authority already in `contracts/` compiles into exactly one
> executable representation per plane — Arrow objects for data, a typed
> semantic execution DAG whose relational nodes contain DataFusion
> `LogicalPlan`s and whose graph nodes contain `GraphOperatorPlan`s, and
> generated registry types for vocabularies — and no consumer is permitted a
> second encoding.** Where an authority is missing
> (fingerprint domains, request identity, evolution policy, golden answers), it
> is created as a contract first and compiled second.

Mapped onto the fabric stack of `PRIN §8` and `ALIGN §2.1`:

```text
contracts/ (schema IR · registries · identity · bundles · policy)   ← authorities
        ↓ one compiler per authority (model drivers)                 R1, R10
generated Rust/Python/proto/Arrow forms, digest-linked               R1
        ↓
QuerySpec → typed semantic DAG → LogicalPlan and GraphOperatorPlan  R2, R3
        ↓
TableProviders with truthful pushdown/statistics/constraints         R6
        ↓
validated RecordBatch streams; IPC at process boundaries             R5
        ↓
Delta commits + snapshot manifests + plan artifacts, all pinned      R4
        ↓ observed through
phase-tagged errors · persisted QueryPlanArtifact · explain surface  R4, R7
        ↓ proved by
contract-named oracles · executable Gate B · convergence comparator  R9
        ↓ presented by
a thin adapter over one proto boundary family                        R8
```

### R11 — Accepted normative ownership and detector-backed current truth

**Intent.** No implementation packet may claim alignment from routed design
questions, a stale detector result, or an unattributed dirty baseline. This
move is a prerequisite to R1–R10, not a certification afterthought. (`PRIN P2`,
`P10`, `P14`, `P19`, `P21`, `P25`; `HOL P29`, `P31`.)

**Mechanism.**

- Apply §6's exact amendment decisions to `SUITE`, `FAB`, `QRY`, `LIFE`, and
  `GEN`; obtain the repository's normal accountable acceptance before code
  execution. A generated traceability oracle must map all 25 principles and
  every active conformance finding to an accepted normative clause, owning
  remediation move, and executable proof.
- Re-run every DP-001–DP-124 detector at the selected v2 baseline using the
  detector's declared coverage envelope. Publish a superseding conformance
  review classifying each row `open`, `partial`, `closed`, `invalid`, or
  `changed`; regenerate §4's finding-to-move projection from that artifact.
- Establish a baseline-owner decision for every dirty/untracked/deleted path
  before the first proving commit. Untracked removal requires an owner-approved
  recoverable archive or manifest; Git revert is not a recovery mechanism for
  bytes Git never owned.
- Install oracle-substance governance before any implementation oracle can
  close a packet: governed criterion IDs, alias rejection, selector
  reachability, and `--no-tests=fail` are foundational.

**Closes.** The design premises behind audit F-001, F-004, F-011, and F-016;
implementation mapping remains conditional on the superseding register.

**Evidence.** `design-principle-traceability-check`,
`alignment-detector-check`, `audit-baseline-check`, and
`oracle-substance-check` are executable release gates, not hand-maintained
tables.

### R1 — One identity, fingerprint, and registry authority

**Intent.** End the P3 pattern at its source: every enum vocabulary and
semantic-identity/fingerprint recipe has exactly one authority in `contracts/`,
one generated projection per language, and an executable drift oracle.
Integrity digests, cache keys, and keyed security authenticators remain
separate authorities because they have different semantics and threat models.
(`PRIN P3`, `P18`; `ALIGN` P3, P18; patterns `MOD-04`, `MOD-06`, `SCH-10`,
`OBS-09`.)

**Mechanism.**

- **Purpose-classified digest authorities.** A structural census covers
  `blake3::Hasher`, one-shot `blake3::hash`, keyed constructors, imports, and
  renamed calls across Rust, Python, tooling, tests, and generated consumers.
  Each use is classified as semantic identity/fingerprint, integrity, cache,
  or security/MAC. Only the semantic identity/fingerprint records enter the
  new `contracts/identity` registry (domain string, framing, field set/order,
  normalization, and compatibility policy) and compile through
  `crate::identity`. Integrity and security operations retain narrow,
  separately named authorities. This subsumes the duplicated
  `capability-scope` fingerprints (DP-086, DP-119), the twice-implemented
  `fact_evidence` identity (DP-031), and semantic uses of the independent
  `digest_bytes` definitions without pretending every hash is an identity.
- **One registry module per language, generated, imported.** The
  `registries.rs` / `model_registries.rs` twin emission (DP-040) collapses to a
  single generated Rust module; the governed Python registry module becomes the
  imported one by fixing the `role_for` path-matching defect
  (`repository_model.rs:825-829`) that currently governs the orphan and ignores
  `model_registries.py` and `identity.py` (DP-001, DP-003). The hand-written
  `NewlineKind` and `FreshnessState` re-declarations are deleted in favor of the
  generated enums (DP-039, DP-118), and the crosswalks they required disappear.
- **Registry→proto emission.** Wire enums in `contracts/rpc/*.proto` whose
  domain exists in `enum-registry.yaml` are generated from the registry by the
  proto driver, ending the `QueryExecutionState` double authority (DP-002). Wire
  codes are read from registry records, never reconstructed by array-position
  arithmetic (DP-085).
- **Normalization in generated recipes.** The CBEF recipe generator emits the
  `normalization: ASCII_LOWER` contract field it currently drops, so the
  generated path can honor `cbef-v1.yaml` before
  `model-no-positional-cbef-construction` pushes production onto it (DP-005).
  Public IDs mint only through `identity::encode_public_id` (DP-098 ◐).
- **Cross-root agreement by generation, not duplication.** The
  daemon/extractor `digest_frames` pair (DP-083) is emitted by the model
  compiler into both Cargo roots from one template, with a byte-equality oracle
  — model-derived duplication with drift detection, respecting the dated-nightly
  toolchain boundary (no shared crate; `AGENTS.md §1`).
- **Authority reads at startup.** Advertised digests are read from the installed
  artifact they describe — the query-language bundle digest comes from
  `contracts/bundles/query-language-bundle.json` at build or bootstrap, never
  from a copied literal (DP-076). Registry vocabularies referenced by the golden
  corpus and query plane are imported from generated constants
  (DP-095 ◐, DP-121 ◐, DP-122: the six-place query-form vocabulary becomes a
  registry domain with serde renames derived from it).

**55/59 leverage.** None required — this move is the application-overlay half of
`ALIGN §0.3` ("durable semantic-model registry" is explicitly not supplied by
the libraries). Its Arrow-facing consequence is that every generated schema and
registry projection carries the digest link that R6 validates.

**Closes.** DP-001, DP-002, DP-003, DP-005, DP-031, DP-039, DP-040, DP-044
(digest half), DP-076, DP-083, DP-085, DP-086, DP-095 ◐, DP-118, DP-119,
DP-120, DP-121 ◐, DP-122; enables DP-017/DP-117 closure in R7.

**Evidence.** Registry-conformance KATs decoded by both languages from shared
fixtures; a purpose-aware digest-domain census oracle (each use maps to exactly
one authority and every semantic domain is registered); byte-equality oracle
across the two roots; constructor and one-shot structural rules promoted into
the tested ast-grep harness. (`TST-01`, `TST-14`; `DFREF §32`.)

### R2 — The semantic query plane becomes a typed multi-backend execution DAG

**Intent.** Replace the `format!`-built SQL string and compile-time-constant
response states with the compiler chain already specified by `QRY`:
parsed request → typed request → snapshot-bound plan spec → typed execution
DAG → physical execution → observed result. DataFusion owns relational
semantics; application graph operators own graph semantics. (`PRIN P1`, `P2`,
`P6`, `P14`; `QRY §§4.2–4.10, 15–17, 21, 30, 33, 106–107`; `ALIGN` patterns
`MOD-02`, `MOD-03`, `MOD-05`, `MOD-07`, `LOG-01`–`LOG-07`, `EXP-01`,
`EXP-02`.)

**Mechanism.**

- **All eight forms and arbitrary composition.** The semantic envelope parses
  into `ParsedSemanticRequest`, then `TypedSemanticRequest`, then a
  snapshot-bound `BoundPlanSpec`. Typed edges represent prior-result roles;
  cycle rejection, fan-in/fan-out, block identity, source JSON pointers,
  boundedness, coverage effects, and cancellation behavior are decided before
  snapshot work. Unsupported forms are advertised before execution until the
  complete conformance matrix is released.
- **Two explicit execution node families.** Relational selections,
  projections, joins, filters, aggregates, and summaries lower through
  `Expr`/`LogicalPlanBuilder` against the serving session's `DFSchema`s.
  Traversal, connecting paths, and conjunctive graph patterns lower to typed
  `GraphOperatorPlan` nodes over the application graph substrate. Both consume
  and produce declared Arrow schemas; a scheduler executes the acyclic DAG and
  never hides graph semantics inside SQL text, a UDF, or an opaque DataFusion
  extension.
- **Semantic policy before lowering, structural policy after lowering.** The
  evaluative-request refusal and fact-equivalent rewrite operate on the typed
  semantic request, where intent is still visible. A separate post-binding
  allowlist validates tables, functions, and plan/operator node families.
- **Canonical response semantics.** Every result form declares a total
  semantic order. DataFusion `SortExpr`s or graph-operator ordering are applied
  before offset/fetch and before response encoding. Coverage, explicit unknown,
  negative-proof, and absence states are typed outputs rather than empty-row
  inference.
- **Advertised filters and result states become real.** `QueryInput`,
  `QueryPredicate`, projections, and limits compile through the same typed
  pipeline or are withdrawn. Generated registry enums are computed from
  execution facts: limit state from fetched versus produced counts, freshness
  from the live barrier on success and failure, and completeness/unknown from
  coverage effects. Limits fingerprints hash their values through R1.
- **Activation.** `daemon::serve` constructs the continuous engine and query
  service, advertises exact per-form support, and proves every supported form
  end to end. `CORE_SOURCE_V1` coverage reaches the status surface rather than
  dead-ending in a test.

**55/59 leverage.** `SessionState`-scoped catalog/config snapshots,
`LogicalPlanBuilder`, `Expr`, `SortExpr`, optimizer visibility, and Arrow-native
batch exchange serve the relational nodes. They are composed with—not stretched
to replace—the application graph kernel required by `QRY`.

**Closes.** DP-075, DP-077, DP-080, DP-095, DP-098, DP-105 ◐, DP-109, DP-110,
DP-111, DP-112 ◐, DP-123, subject to R11's superseding register.

**Evidence.** `semantic-query-conformance-check` executes all eight forms,
independent and dependent blocks, fan-in/fan-out, cycle rejection, bounded and
shortest paths, patterns, summaries, unknown/coverage/absence cases, canonical
ordering, and unsupported-form advertisement through the daemon. Relational
subplans additionally prove optimized/unoptimized equivalence; the old
three-form SQL path is a transition comparison only, never the contract oracle.

### R3 — Deterministic result identity and modeled reproducibility

**Intent.** Make `result_checksum` a truthful function of the query and
snapshot, and make reproducibility a modeled status rather than an implied
promise. (`PRIN P19`; `ALIGN` P19; patterns `MOD-06`, `OBS-10`, `RUN-10`.)

**Mechanism.**

- **Canonical delivered order.** R2 imposes each form's total semantic order
  before offset/fetch. The public response bytes and pagination therefore stay
  stable across partitioning and batch boundaries; checksum ordering is not
  used as a substitute for response ordering.
- **Versioned `ResultChecksumV1`.** The checksum hashes a canonical output
  schema encoding (field names, types, nullability, ordered metadata, extension
  metadata), row count, and length-framed sorted row encodings. The semantics
  are a multiset: duplicate multiplicity changes the value. The contract fixes
  `SortOptions`, nulls, dictionary normalization, Map-key policy, signed zero,
  NaN, nested/view/extension fields, empty and zero-column batches, memory
  bounds, and the exact Arrow/`arrow-row` compatibility domain. A version move
  rejects or migrates; it never silently restamps identity.
- **Three identities, not one overloaded hash.** A plan-template/cache
  fingerprint identifies reusable execution structure. A semantic query
  identity additionally includes canonical bound `QuerySpec`/parameter bytes,
  snapshot-manifest digest, and configuration fingerprint. Request/caller and
  execution identities remain correlation/provenance identities in R4.
- **Versioned plan serialization.** The fingerprint names the plan phase and
  canonicalizes typed semantic DAG nodes, relational expressions, graph
  operators, aliases/qualifiers, scalar values, table/provider identities,
  functions, child ordering, and engine/codec version. Same-version
  `datafusion-proto` bytes may be used only inside an explicitly pinned
  compatibility domain; display text and Rust `Hash` are not durable authority.
- **Reproducibility status.** `QueryPlanArtifact` gains the `Reproducibility`
  record of `PRIN §20` — `deterministic`, `inputs_pinned`,
  `volatile_functions`, `environment_recorded` — derived from the plan (no
  volatile functions exist today; the field exists so the claim is checked, not
  assumed) and from `RUN-10` environment capture.

**Closes.** DP-012; provides the mechanism half of the register's P19 row (the
normative home routes to `LIFE` per §6).

**Evidence.** `query-determinism-check` varies partitions, batch sizes, row
arrival, and pagination while asserting identical response order/bytes and
checksums. Golden identity tests cover duplicate multiplicity, dictionaries,
Map order, nulls, signed zero/NaN, nested and extension fields, empty and
zero-column batches, semantic mutations, exact retry, and same-template
different-parameter separation (`TST-06`, `TST-14`).

### R4 — Provenance closure: the artifact plane, execution identity, and retained lineage

**Intent.** Every durable result resolves the chain of `PRIN §11` — commit →
execution → plans → spec versions → input versions → schema fingerprints →
source snapshots — through stored references, and the richest diagnostic
artifact in the system stops being dropped. (`PRIN P9`, `P10`, `P17`, `P24`;
`ALIGN` P9, P10, P17, P24; patterns `OBS-01`–`OBS-12`, `RUN-05`.)

**Mechanism.**

- **Persist the artifact bundle.** `QueryPlanArtifact` — already carrying
  logical/optimized/physical plan text, versions, snapshot and publication IDs,
  source table versions, output schema, metrics — is written to
  `result_artifact_lease` (its designed home with zero INSERT sites, DP-036),
  keyed by execution identity, with the retention policy `ALIGN` P17 requires.
  Ordinary `EXPLAIN` remains a planning artifact. Metrics are rendered from the
  exact physical plan instance that produced the served rows through
  `DisplayableExecutionPlan::with_metrics`/`with_full_metrics` and PG-JSON.
  `EXPLAIN ANALYZE` re-execution is prohibited on the governed serving path
  because `AnalyzeExec` executes and discards its input.
- **Complete the artifact's pin.** The artifact records all seven manifest
  bundle IDs, overlay generation/digest, and overlay-supplied table versions —
  not 1 of 7 and base tables only (DP-056) — and the control-schema capture is
  stamped with a generation fingerprint recorded alongside
  `source_table_versions` (DP-035), turning the one unversioned cache in the
  fabric plane into a `RUN-08`-conformant entry.
- **Request and execution identity in Rust.** `semantic_request_id` and
  `mcp_call_id` enter the daemon (proto → handler → artifact → trace), and an
  `execution_id` is allocated *before* planning (`ALIGN` §11 flow), propagated
  through `TaskContext` (`RUN-05`) and tracing spans (`OBS-06`). Two agents
  issuing semantically identical requests become distinguishable at the fabric
  layer (DP-053).
- **Join keys that join.** `provider_run.owner_id` is encoded as the same
  16-byte Id16 every fact table length-checks, restoring the one
  provider-run→fact join (DP-023). R11 re-derives DP-022 because the continuous
  engine already records `update_wave`/`update_wave_item`; only residual
  identity, completeness, or reachability defects from the superseding
  detector remain eligible work. `table_mutation_operation` gains typed scope
  columns (`workspace_id`, `analysis_context_id`, `source_generation`,
  `wave_id`) and a `workspace_scope`, ending join-by-substring; the three
  no-preimage digest keys either gain stored preimages or are re-documented as
  integrity (not provenance) fields (DP-054).
- **Evidence and diagnostics reach their tables.** Derived relations get
  evidence rows through the same accumulator the other projections use
  (DP-026); `IngestDiagnostic`/`ConflictRecord` are written to the `diagnostic`
  table (DP-050); provider attribution carries the producer the call site
  already knows, plus `derivation_code`, instead of six constants (DP-024 ◐
  with R5). `capability_status` population is completed: `reason_code` and
  `diagnostic_id` are emitted so *unknown* is expressible, and the query
  service advertises real statuses instead of `Vec::new()` (DP-013 residual).
- **The snapshot's source link is persisted.** `source_blob_digests` joins
  `ServingSnapshotManifestBody`, making the snapshot→bytes link
  content-addressed rather than a nullable lease field (DP-052). For fact-row
  identity, §6 adopts `GEN §13`'s existing distinction: `file_id` is exact
  workspace-relative file identity within the source snapshot; occurrence
  identity additionally includes source digest/range, normalized occurrence
  family/role, structural anchor, and owner. A pinned manifest makes those
  inputs resolvable; a location identifier alone is never fact identity.
- **Retention respects closure.** `SnapshotRetentionSet` unions provenance
  reachability — retained publications protect their `provider_run`,
  `table_mutation_operation`, `source_inventory`, and source-blob explainers;
  terminal cleanup checks publication reachability before deleting (DP-027).
- **An explain surface.** `explain_version(table_code, delta_version)` reads
  Delta `history()` commit metadata and the artifact store, giving operators
  the "why does this row exist" traversal (DP-055; `OBS-12`; deltalake
  `history()` per the delta-rs reference).

**55/59 leverage.** Physical-plan metrics rendered in the PG-JSON explain
format (`DFREF §30`) make the bundle machine-diffable without re-execution;
`file_row_index()`
(`ALIGN A.1`) is available for file-relative provenance if source-image ingest
later flows through file scans — recorded as a candidate, not selected now.

**Closes.** DP-013 (residual), DP-015 ◐, DP-022, DP-023, DP-024 ◐, DP-026,
DP-027, DP-035, DP-036, DP-050, DP-051 (contract + routing), DP-052, DP-053,
DP-054, DP-055, DP-056.

**Evidence.** A closure-traversal oracle: from a committed Delta version,
resolve commit → execution → artifact → spec/schema/source identities, failing
on any missing link (`OBS-12`); failure-path tests asserting a partial bundle
exists through the failing phase (`ALIGN` P17 evidence); retention tests
proving a retained publication's explainers survive GC.

### R5 — One Arrow fact contract with boundary-appropriate transports

**Intent.** One typed Arrow contract and one validation/ingest pipeline for
facts, with transport selected by the actual boundary and the provider
hierarchy made real. (`PRIN P4`, `P5`, `P7`, `P8`, `P22`; `ALIGN` P5, P7, P8;
patterns `ARR-03`, `ARR-08`, `ARR-10`, `INT-01`, `INT-08`, `CAT-10`.)

**Mechanism.**

- **One contract, two transport adapters.** In-process Tree-sitter/Ruff
  adapters yield bounded validated `RecordBatch` streams. Rustc/Pyrefly
  subprocess adapters use Arrow IPC decoded by a push-based `StreamDecoder`.
  Both converge before `ValidatedFactBatch::validate`; transport identity does
  not change semantic batch identity. `ObservationMessage`, `CanonicalFact`,
  and the four-of-ten-tables ceiling retire in favor of schema-driven coverage.
- **An honest IPC profile.** External streams keep validation enabled, accept
  arbitrary byte chunking, call `finish()` to detect truncation, and default to
  `require_alignment=false`, which copies only unaligned buffers while
  preserving zero-copy aligned buffers. Memory alignment is not wire metadata.
  Compression/codec and stream-format version are protocol fields; corruption,
  truncation, schema mismatch, and resource bounds are negative cases.
- **One ingest pipeline.** The projection and observation paths (DP-030) merge
  above `ValidatedFactBatch::validate`: one row-budget mechanism, one
  provider-precedence table (the explicit `BTreeMap` sort), one
  conflict-disposition and evidence encoder, and schema-fingerprint fencing on
  every path. Row-local type, shape, and key checks occur here; cross-table
  referential enforcement belongs to R6's complete candidate publication.
  Arrow 59's fallible
  `FixedSizeBinaryArray::TryFrom` construction (`ALIGN A.2`) turns Id16 shape
  defects into contract-validation failures at the boundary.
- **The provider hierarchy becomes real.** `TreeSitterAdapter` and
  `RuffAdapter` implement `ProviderAdapter` (DP-009); the ingest entry point
  takes a registry-driven collection of adapter outputs instead of a signature
  fixed to `(tree, ruff)` (DP-010), so adding Pyrefly or the rustc extractor
  changes registration and one implementation — the `PRIN §6` design test.
  The two hand-maintained field-role tables (DP-033) become one generated
  crosswalk registry (provider raw role → `SyntaxFieldRole`), with the current
  semantic coercions either declared as records or removed.
- **Provider facts survive the boundary.** `evaluation_ordinal`,
  `source_ordinal`, line/column, `depth`, and provider-parsed names are carried
  as batch columns instead of being dropped and re-derived downstream
  (DP-032); attribution columns carry the true producer and derivation rule
  (DP-024 ◐ with R4). `RuffTokenClass`→`TokenKind` narrowing becomes a declared
  registry mapping or is removed in favor of the raw-plus-normalized pair the
  doctrine requires ("raw and normalized coexist").
- **One cancellation type.** The five unrelated cancellation encodings
  (DP-011) collapse to one `Cancellation` handle threaded from the RPC
  boundary through provider execution to stream polling — the structural
  precondition for `SRV §6` inv. 10's end-to-end cancellation, which R8
  completes at the adapter.
- **One extractor seam.** The `--extract-json` bypass protocol (DP-084) is
  deleted; the gRPC + Arrow IPC path becomes the tested path, and the
  extractor's determinism oracle runs against it. `ProviderJobSpec` stops being
  the domain type: a domain DTO owns the seam and the prost message is confined
  to the rpc adapter (DP-047), ending the lossy `ScopeBegin`→`Progress` string
  collapse.
- **Runtime state hygiene.** `AdmissionController` maps gain eviction tied to
  workspace lifecycle, and `SourceImageStore`'s ownership doc-comment is made
  true (coordinator-owned) or corrected (DP-049).

**55/59 leverage.** `RecordBatchReader`/bounded streams in process;
`StreamDecoder`, IPC compression, and sans-I/O encoding across processes;
`TryFrom` fallible construction; Arrow kernels for batch-level normalization
(`ARR-06`) instead of row loops.

**Closes.** DP-009, DP-010, DP-011, DP-024 ◐, DP-028, DP-029, DP-030, DP-032,
DP-033, DP-047, DP-049, DP-084.

**Evidence.** The provider-contract suite runs identically over direct-batch
and IPC adapters (`TST-02`). IPC tests cover every-byte splits, valid unaligned
buffers, `finish()` truncation, corruption, and resource limits only on
external seams (`TST-09`). Cancellation propagates from RPC to stream drop
(`TST-10`), and the merged pipeline differentially reproduces the accepted
corpus without requiring in-process serialization.

### R6 — Truthful `TableProvider`s and executable schema contracts

**Intent.** The serving plane's capability claims become exact, inexact, or
absent — never decorative — and the schema IR's declared semantics (foreign
keys, semantic types, normalization, evolution) become enforced or explicitly
reclassified. (`PRIN P12`, `P20`, `P21`; `ALIGN` P12, P20, P21; patterns
`SCH-01`–`SCH-12`, `CAT-05`–`CAT-07`, `GOV-06`, `GOV-07`.)

**Mechanism.**

- **Statistics and pushdown truth.** The overlay provider's `statistics() ->
  None` plus asserted-because-set pruning/repartition flags (DP-019) are
  replaced by `Statistics` with honest `Precision::{Exact, Inexact, Absent}`
  per column for the complete effective relation; a replacement batch's exact
  count is not automatically an exact base-minus-tombstones-plus-overlay
  count. Delta-backed tables report only what authenticated snapshot Add-file
  statistics support. Per-predicate `TableProviderFilterPushDown` declarations
  remain truthful under `scan_with_args`/`ScanArgs` (`ALIGN A.1`; `DFREF §18`,
  `§51`, `§47`). `ServingRuntimeEvidence` records observed pruning and
  repartitioning from the one served physical plan's metrics.
- **Requested statistics are optional end to end.** `StatisticsRequest` is not
  adopted merely because `ScanArgs` exposes it. Adoption requires a named
  optimizer rule that requests cheap statistics, a returned-plan
  representation and consumer, no planning-time I/O, and explicit
  cost/staleness policy. Until that complete path exists, requests remain
  unanswered and CAT-07 is explicitly declined rather than simulated.
- **Constraints verified, not just installed.** `validate_open_table` checks
  `delta.constraints.*` against the generated spec on every serving open, and
  constraint installation moves after table authentication (DP-020). The
  CHECK-constraint claim becomes a verified property of the opened table.
- **Metadata reclassified per the six semantic classes.** Every schema-IR
  annotation is classified enforced, planner-consumed, contractual,
  governance, lineage, or advisory with a named consumer (`PRIN P21`;
  `GOV-07`; `DFREF S7`). `foreign_key` is promoted to enforced over the
  complete candidate effective snapshot after owner replacements/tombstones
  and before publication CAS/activation (14 annotations, today decorative;
  DP-021). Ingest retains only row-local checks. The SQLite generator either
  emits `REFERENCES` clauses or the `foreign_keys` pragma is removed with the
  decision recorded. `semantic_type`
  strings are validated against the enum registry with a digest link between
  the schema IR and the registry (the ~14 unresolvable of 28 become build
  failures; DP-043). `fact_evidence.fact_form_code` gains its registry binding
  and one sourcing rule (DP-025). `TableSpec::dependencies` and
  `zorder_columns` either gain consumers (publication ordering; Delta table
  properties written and verified) or are removed as metadata theater.
- **IR-owned values emitted, not re-typed.** `ontology_version` and
  `compatibility_mode` are emitted by the schema driver into the runtime
  constants that currently hard-code them (DP-034); row encoders are generated
  from the same IR that generates the specs they are hand-checked against
  (DP-038), eliminating the ~161 hand-written column tuples as drift surface.
- **Evolution policy declared.** The de-facto "no evolution" pin —
  `enableTypeWidening=false`, digest-equality hard reject, no acceptance suite
  (DP-037) — becomes a stated contract: a schema-evolution policy artifact
  declaring the compatibility classes accepted (currently: exact-pin), the
  migration route when the pin must move, and the generated compatibility
  acceptance suite `schema-validation.json` falsely gestures at.
  `Schema::try_merge`/`contains` are the mechanisms; the policy is the
  authority (`SCH-04`; `DFREF S5`, `S6`). `FAB` App. C inv. 11's "explicit and
  versioned" requirement is met by making the pin explicit and versioned.
- **Domain identity as an application-enforced extension contract.** Id16
  columns use Arrow's `ExtensionType` metadata
  (`codefabric.id16` over `FixedSizeBinary(16)`) for type-safe metadata
  serialization and IPC/Parquet preservation; unknown consumers degrade to
  the storage type. Application schema validators enforce and deliberately
  reattach/reject the metadata through projection, cast, and evolution.
  DataFusion's separate `DFExtensionType`/registration may be added for
  formatter behavior only. DataFusion 55 does not make casts, planning, or
  execution honor custom semantics automatically, so the registry is never
  cited as enforcement.
- **Instance validation.** The eight public JSON schemas gain instance
  validation — golden envelopes validated against `planspec.schema.json` and
  siblings in CI, replacing key-set comparison (DP-063 ◐ with R9).

**Closes.** DP-019, DP-020, DP-021, DP-025, DP-034, DP-037, DP-038, DP-043,
DP-063 ◐; with R1's normalization fix, DP-005.

**Evidence.** Adversarial pushdown/statistics tests cover overlay and tombstone

### R7 — Lifecycle phases, one error vocabulary, and guard truth

**Intent.** Failures identify their phase; public error identity is registry
membership, not a `Display` substring; state-machine guards are evaluated, not
merely legal. (`PRIN P16`, `P20`; `ALIGN` P16; `LifecycleArtifactMap` with
phase-scoped failure codes; `DFREF §33`, `§41`.)

**Mechanism.**

- **Phase on every error.** A generated `Phase` enum (from the lifecycle /
  state-machine registries) becomes a structural field of the fabric error
  types — the `ALIGN` §17 failure-code scheme (`schema_binding`,
  `logical_planning`, `policy_validation`, `physical_planning`, `execution`,
  `write_validation`, `commit`, …). The 439-variant, zero-phase census (DP-016,
  DP-096) is retired not by editing 439 variants but by making phase a
  property of the error *envelope* every subsystem returns; `String`-typed
  error plumbing in the extractor wrapper gains a real error type.
- **Registry-closed public identity.** Every `CODE:`-prefixed public error is
  a member of `PUBLIC_ERROR_IDS`, enforced by the DP-117 detector promoted to
  a gate; the shadow vocabularies (`LIFECYCLE_*`, `CONTINUOUS_*`,
  `DERIVATION_*`) are registered or renamed to registered codes, and the
  registered codes naming exact conditions (`QUERY_HARD_LIMIT_EXCEEDED`,
  `SEMANTIC_PHRASE_*`, `INVALID_REQUEST_SCHEMA`) are raised where those
  conditions occur (DP-017, DP-117). The error registry's `grpc_status`,
  `severity`, `retryability`, and `mcp_mapping` columns are generated into the
  Rust projection and consumed at the RPC boundary (DP-018), collapsing the
  ten independent code vocabularies to one generated one plus declared
  domain-local diagnostics.
- **Traces that survive failure.** Stage traces are recorded incrementally —
  each stage appends before the fallible call, so a failure names its phase
  (DP-015; same shape in `snapshot_catalog` and `snapshot_runtime`).
- **Observability that observed.** Daemon shutdown logs each step *after* it
  completes and reports only completed steps in `DaemonExit` (DP-014).
- **Guard truth.** `generated_transition` verifies legality; the continuous
  engine additionally *evaluates* guards before asserting them — a wave
  containing files whose language requires semantic capability cannot declare
  `semantic-work-not-applicable`; the state registry's opposite branch is taken
  and the wave parks in the explicit not-yet-terminal state (DP-079). This is
  the wave-level enforcement of `RM §1` inv. 6 (absence is never proof).

**Closes.** DP-014, DP-015, DP-016, DP-017, DP-018, DP-079, DP-096, DP-117.

**Evidence.** Phase-injection tests failing each lifecycle phase and asserting
the reported phase (`MOD-05` evidence; `ALIGN` P16); the error-registry

Rust-bearing wave and asserting it cannot reach `required-capabilities-terminal`
without the semantic lane.

## 6. Normative amendments required for certification

R11 applies these decisions to the owning specifications. They are no longer
open-ended routing notes. M14 cannot certify until the amended artifacts are
accepted and their digests are declared plan inputs.

1. **P2 — executable models (`SUITE`, AC-G-05).** Every governed semantic
   authority names at least two derived operations where the model has more
   than one consumer, and each generated projection carries authority identity
   plus a drift oracle. Consumers may not privately re-encode the semantics.
2. **P10 — provenance closure (`FAB` / `LIFE`).** From every durable served
   result or Delta version, the system shall resolve commit, execution,
   semantic request and plan artifact, specification/schema/input versions,
   and source snapshot/blob references. Retention and GC shall preserve every
   node reachable from a retained result; a missing link is an explicit
   capability/provenance gap.
3. **P14 — extension decisions (`FAB` / `QRY`).** Every non-built-in execution
   mechanism has a versioned `ExtensionDecisionRecord` stating the required
   semantics, highest viable extension level, alternatives rejected,
   optimizer/observability effects, owner, and executable proof. Relational
   semantics use built-in DataFusion nodes. Required graph semantics use the
   typed application `GraphOperatorPlan`; any custom DataFusion logical or
   physical extension reopens design.
4. **P19 — reproducibility (`LIFE`, AC-G-79).** Every governed execution records
   the versioned semantic query identity, plan identity, input/snapshot and
   configuration fingerprints, software/library domain, output checksum
   contract, and modeled reproducibility status. Unsupported volatility or
   environment capture is explicit, never inferred as deterministic.
5. **P21 — metadata classes (`FAB`, AC-G-20).** Every metadata field belongs to
   exactly one of six classes: enforced, planner-consumed, contractual,
   governance, lineage, or advisory. Non-advisory fields name an authoritative
   consumer and enforcement/validation point. Metadata presence alone never
   implies runtime semantics.
6. **DP-051 — source and occurrence identity (`GEN §13`).** `file_id` denotes
   exact workspace-relative file identity within a source snapshot. A source
   occurrence identity additionally includes the source digest/range,
   normalized occurrence family/kind and role, structural parent/field/ordinal
   anchor, and owner. Location identity alone is not fact identity; the serving
   manifest pins the inputs required to resolve the occurrence.

## 9. Explicit non-goals and preserved divergences

- **The divergence ledger stands.** No tenancy predicates or multi-tenant
  policy model (`SRV §6` inv. 4); no classification/retention/masking
  metadata (`FAB` App. D); no advisory display-name channel (`AC-G-54`); no
  user-facing `Expr` transparency (`SRV §6` inv. 5). `ALIGN`'s GOV-02/GOV-05
  tenancy patterns are deliberately not selected.
- **No new extension levels.** No custom `ExecutionPlan`, `PhysicalExpr`,
  planner, UDF, or `LogicalPlan::Extension` (`EXT-04`–`EXT-10` unselected);
  `GraphOperatorPlan` is an application semantic-plan family, not an opaque
  DataFusion node. The P15 row is conformant because relational semantics stay
  visible to DataFusion and graph semantics stay inspectable in their native
  typed plan.
- **No new Cargo roots, no `crates/`,** and no module decomposition mandates —
  the scope boundary of `AGENTS.md §1` is untouched; moves name behaviors and
  contracts, not file layouts.
- **No Substrait/Flight adoption.** Subprocess boundaries remain UDS gRPC +
  Arrow IPC while in-process providers use Arrow batches (`INT-01`, `INT-08`);
  `INT-05`/`INT-07` are recorded as
  reviewed-and-declined for a single-host daemon (`ALIGN` P22: protocol per
  boundary semantics, not capability availability).
- **Delta writes stay behind the existing boundary.** `MERGE INTO` /
  `TableProvider::merge_into` (`ALIGN A.1`) is noted for the overlay
  publication path but not selected; the current mutation boundary satisfies
  P11 and is the register's strongest row.
