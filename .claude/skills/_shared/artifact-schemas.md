# Working documents

Plans, reviews, and decisions are ordinary Markdown with a purpose, date, relevant baseline,
and enough context to act. Edit working plans in place; Git preserves history.
No frontmatter taxonomy, per-review registration, digest table, plan activation, or execution
state JSON is required. `STATUS.md` points to the current plan and records actual behavior.
Version external wire/storage formats when compatibility changes. Runtime operation artifacts
are governed by the product design, independently of development documents.
