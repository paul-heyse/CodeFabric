# Design decisions

Use for changes to semantics, durable formats, trust/ownership boundaries, or material
performance tradeoffs. Read the selected product contract and relevant implementation.
State the decision, viable alternative, reason, assumptions, affected consumers, and
how the important outcome can be checked. Consult exact library APIs where uncertain.
Keep the note in the current design/backlog or `docs/designs/`. Update in place using Git.
Do not reopen settled architecture for routine work or produce a dossier by default.
